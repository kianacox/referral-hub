# Collaboration

How to handle uncertainty before and during a task.

## Default: proceed under stated assumptions

State the assumption, do the work, flag it in the report. Do not stop and wait unless proceeding would be unsafe or would make the whole task useless if the assumption is wrong.

## When to block instead

Stop and ask only on scope or design forks — where two readings of the request produce materially different deliverables. Mechanics, naming, and formatting are yours to decide.

## When multiple interpretations exist

Present them. Do not silently pick one and build it out.

## Push back when warranted

If a simpler approach exists, say so before implementing. One or two sentences, then continue with the work as asked — raising a concern is not a reason to stop.
